# 聊天可靠性修复计划

范围：当前 master 的 Obsidian 插件及已确认的 13 个异常场景；不切换到实验内核分支。

## 实施顺序与验收标准

1. **保全与会话状态**：保存现有控制台日志和可见对话备份；用户消息、模型消息、工具结果逐步持久化。压缩上下文不改写原始历史；停止、异常、重载后可恢复，导出不再依赖界面残留。
2. **执行生命周期**：统一普通聊天/工具聊天的开始、完成、失败、取消；事件携带 agent/session/run 标识；停止不返回空成功，子任务不结束父界面，失败继续向调用方传播。最后一轮正常完成不误报熔断。
3. **工具执行边界**：开始前检查取消；超时和取消传入工具；不把“停止等待”当成“副作用已停止”；清理定时器/监听器；按 invoke 目标分类、写操作串行、只读有界并发且实时显示开始。
4. **模型与配置**：修复路由读写位置并迁移旧根级字段；按真实 embedding 能力路由；配置错误不重试、不创建无向量的成功索引；保留异常原因。模型流不完整时禁止执行工具，不自动重放已经产生副作用的任务。
5. **诊断**：会话、请求、工具、取消、存储失败统一落盘并脱敏；错误日志包含会话与执行标识；允许无历史导出，读取失败明确提示；使用实际模型/上下文窗口，区分累计消耗与当前上下文占用。
6. **验证与交付**：将离线诊断转为回归测试；运行类型检查、相关测试、完整测试和构建；复核差异。部署仅到用户指定 vault，先备份现有插件与配置，保全当前对话后再重载，并独立读回验证。

## 验证矩阵

- 跨两次提问的历史、重载、完整工具消息、失败/取消/压缩后的原始历史。
- 流等待时取消、已取消调用、空/截断流、普通聊天结束、正常达到最后一轮。
- 两个 invoke 写同一文件、只读并发上限、开始事件时机、子 agent 事件隔离。
- 工具协作取消、超时后未协作操作的状态与后续写入隔离、授权等待时取消。
- 路由选择/旧配置迁移、无向量模型、永久错误不重试、网络错误原始原因。
- 空历史报告、故障发生在最后消息之后、损坏/不可读日志、敏感字段脱敏、指标口径。

## 边界

- 不假设网络变化的来源；保留 ERR_NETWORK_CHANGED 证据并准确提示。
- 旧插件未保存的原始工具历史不能凭界面文本伪造；恢复文本必须标注来源。
- 对不支持协作取消的第三方工具，保留实际完成证据，并在其结束前阻止冲突写入。
- 不新增框架或依赖；复用现有 Agent、EventBus、ChatManager 和平台适配器。

## 已定位的根因与实施结果（2026-11-09）

| 根因 | 修复结果 |
| --- | --- |
| EventBus 改造移除了结果写回，界面有消息但历史为空 | 原始消息逐步 checkpoint，串行写盘；已有文件保留上一份备份，损坏可恢复 |
| 停止流时返回 null，调用方继续读取 usage | 统一可取消流桥接；取消抛出原始原因，保留已生成片段 |
| 普通聊天没有终止事件 | 统一成功、失败、取消的终止事件和界面收尾 |
| 最后一轮正常回答被误判达到轮次限制 | 仅最后一轮仍要求工具时报告轮次耗尽 |
| Promise.race 超时只停止等待，底层仍继续 | 信号传入实际工具；未结束的写操作继续持有隔离屏障 |
| 取消前仍启动工具，授权等待无法取消 | 启动前检查取消，授权、监听器与定时器统一清理 |
| invoke 一律按只读执行，加载器丢失分类元数据 | 保留权限与执行元数据；按目标技能分类，写串行、读有界并发 |
| 子 agent 的全局事件误结束父界面 | session/run/agent 精确匹配，父取消信号传入子任务 |
| 路由控件写根字段、路由器读 taskRouting | 修正写入位置并兼容旧配置迁移 |
| 以服务商类型猜 embedding 能力，缺配置仍重试 | 校验实际 embedding 模型配置；永久错误不重试；无向量不记成功索引 |
| 错误被重新包装、界面统一误导为配置错误 | 保留原始错误和 cause/code，模型与工具故障写入脱敏日志 |
| 导出拒绝空历史，且漏掉最后消息之后的错误 | 空历史也可导出；截止导出时间检索，并注明日志缺失/损坏 |
| 累计用量和硬编码窗口导致假上下文饱和度 | 实际路由模型和配置窗口；最新 prompt 用量与累计消耗分开 |

另补充：压缩只改变模型上下文，不删除原始会话；保存失败时不重复追加回答；截断/不完整的工具调用不执行。
