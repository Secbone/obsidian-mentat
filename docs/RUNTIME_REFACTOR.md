# 运行状态与恢复重构

本轮按五个阶段交付，不新增依赖。保留现有 Agent、Provider、Skill 和主题系统。

1. 类型化执行结果、持久化问答与审批，人工等待不占工具执行超时。
2. 插件级 RunController 持有执行，聊天 View 仅订阅和发送命令。
3. RunStore 保存运行快照、操作账本、交互及有序事件；重载后从完整模型决策恢复，未知副作用不重放。
4. ModelGateway 统一上下文配对、输出预算、截断信息；逐个产物校验、写入、回读并检查点。
5. 诊断使用运行事实，按操作关联错误；区分工具说明查询和实际执行。

验收：人工等待超过 30 秒；审批拒绝/过期/取消区分；关闭页面重开；插件重载后回答原问题；完成工具不重放；未知写入需核对；文件变化使审批失效；截断无工具执行且有用量记录；图格式校验/回读失败不记成功；报告事件不重复。

存储是单插件实例内的串行快照与上一份备份，不宣称跨进程事务或外部副作用 exactly-once。损坏快照回退到备份时采取保守恢复。运行数据只存本地插件目录，诊断导出继续脱敏。

### 用户可见入口

- 聊天底部在等待时显示“回答问题”或“查看并处理审批”，关闭弹窗不提交答案，稍后可重新打开。
- 中断/失败时显示“从检查点继续”；结果未知时先显示“核对实际结果”。未核对的副作用会阻止新的自动任务。
- 命令面板 `Mentat: Open run history and recovery` 可找回已有运行。切换会话不允许覆盖正在执行的其他任务；较旧运行之后已有新对话时，要求打开该会话最新记录。
- 新版会话及全局诊断均包含运行状态、待处理交互、已核验产物和模型请求预算。

### 执行与恢复语义

- 人工交互是持久化状态，通过 `RunSuspended` 结束当前内存执行片段。回答后从已保存的模型决策继续；不序列化 Promise 或生成器。
- 操作开始前保存账本；结果保存后再更新聊天消息。恢复时复用已完成结果。发生在副作用完成与结果保存之间的崩溃，按未知结果处理，不自动重放。
- 父子任务共享根运行存储，操作 ID 及交互 ID 按子任务作用域隔离，子任务消息单独作为检查点保存，不混入父任务的模型工具协议。
- 人工等待、写队列等待、实际工具执行分开；执行超时从真正开始操作时计时，排队时仍可取消。
- 审批绑定操作参数及目标文件内容的 SHA-256，排队后执行前再次校验。该检查不宣称提供跨进程文件事务。
- 流式正文最多每秒保存一次片段，完整响应保存为消息检查点；异常退出可能丢失最后约 1 秒的未保存片段。未完成工具参数不会作为可执行调用恢复。
- 模型上下文与原始历史分开；保留工具请求/响应完整单元，父上下文只接收子任务结果，不复用子任务内部工具消息。
- 继续已达到轮次限制的运行，会开始新的一段受轮次限制的执行；不会无限自动恢复。
- 产物先校验再修改文件，写后回读通过才记录成功；原生 `.excalidraw` 与 `.canvas` 有专门结构校验。压缩的 `.excalidraw.md` 仍使用已有 Markdown 校验，不宣称验证其中压缩绘图内容的可渲染性。
- 原始运行存储在 `.obsidian/plugins/obsidian-mentat/runs/`，暂存产物在同级 `artifacts/`；诊断导出继续脱敏。旧版日志缺少 operationId，保留其可能重复的事实，不猜测合并。
- 无法从主快照或备份恢复的记录会保留原件并暂停自动执行；诊断入口仍可使用。
