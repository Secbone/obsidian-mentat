# 运行日志与排障

## 使用入口

命令面板运行 `Mentat: 打开运行检查器 / Open run inspector`，或从运行历史点击“查看日志”。支持运行筛选、文本检索、只看异常、实时更新、展开详情和导出当前筛选。页面显示最新 200 条，导出保留全部匹配记录。

结构化日志位于 `<configDir>/plugins/mentat/logs/events-*.jsonl`，可直接用 rg 按 runId、requestId、operationId、attemptId、errorId 检索。无需导出 Markdown 或打开开发者工具。历史运行可以从原快照投影；不修改旧会话、审批结果或操作记录。

## 四个部分

- Observer：继承关联上下文、规范化异常、脱敏及大小限制、实时订阅。task 记录起止和异常，保留原异常传播语义。
- LogStore：单写入队列，50 条或 500ms 触发批量追加，错误触发尽快写入；每个文件目标上限 4MiB（一个批次可能超过目标），保留最多 8 个文件。
- RunProjection：复用运行事件，生成尝试、时间线、异常与模型/工具/人工等待耗时；检查器与诊断报告共享计算。
- RunInspectorModal：实时检查与历史检索；只在打开/手动刷新时读历史文件，实时事件不触发全盘重读。

未增加运行时依赖、数据库或远端日志服务。RunController/RunStore 继续是执行和恢复的权威来源。日志不参与审批、重试决定或工具重放。

## 接入范围

运行状态、恢复、模型请求/结果/失败、工具状态、人工交互、产物校验复用已有运行事件 ID。并行事件分别关联，重复导入时可按 eventId 合并。

模型请求另外记录首次进展和每 10 秒的等待/接收状态，不写入运行快照，不记录 token 正文。请求开始记录实际提供商、输出上限与可用的模型/推理配置；旧请求没有的信息保持缺失。

插件初始化/卸载、命令边界、索引失败、技能/上下文加载失败、同步及异步 EventBus 回调失败进入统一记录。全局监听只补充捕获调用栈可识别为本插件的 error/unhandledrejection，不吞掉异常，不接管其他插件。

## 故障与数据边界

- 日志队列最多 1000 条，优先保留较高级别事件。过载/写入失败统计丢弃数，并在下次成功写入时记录 persistence_gap。错误洪峰超过容量时仍可能丢失。
- 内存保留最近 500 条；写入失败可继续查看这些记录。健康状态明确展示写入/读取失败及损坏行。损坏 JSONL 行不影响读取其他行。
- 日志落盘失败不改变业务执行状态；关键运行快照保存失败仍阻止继续执行。
- 密钥先脱敏再截断，正文/参数/思考内容默认省略。限制对象深度、条目数和字符串长度；超大事件保留有限预览。
- 正常卸载会尝试排空；宿主强制结束可能丢失最后一批日志。重启通过运行快照标识未正常结束的执行。
- 轮转只删除日志目录内符合命名规则的事件日志，不删除聊天、运行快照、产物或导出的诊断。
- 模型与工具耗时为累计跨度，可能包含并行/父子重叠，不能直接相加得到总耗时；人工等待单列。旧事件缺失请求 ID 时仅能顺序匹配。

## 验证

浏览器级渲染/宿主崩溃不保证被完整捕获；开发者工具仍用于宿主和渲染问题。第一版不提供自动根因推断或独立证据附件存储。
